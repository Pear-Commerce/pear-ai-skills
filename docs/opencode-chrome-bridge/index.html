Pear Commerce/internal tool/chrome-bridge

chrome-bridge.

An opencode plugin and a Chrome extension that let opencode read and operate your real Chrome browser. The extension uses the DevTools Protocol to snapshot pages, click, type, scroll, take screenshots, and read console/network activity in your actual tabs, with your existing profile and sessions.

16 tools: snapshot · click · type · press_key · scroll · wait_for · screenshot · evaluate · console · network · tab management

install 
curl -fsSL https://raw.githubusercontent.com/Pear-Commerce/pear-ai-skills/main/skills/chrome-bridge/install.sh | bash

Then restart opencode and enable the extension in Chrome (below).

how it works

Three components

The opencode process hosts a WebSocket server on 127.0.0.1:8823. The Chrome extension connects to it. Commands are executed as CDP input in your tabs. There is no cloud component.

01

opencode plugin

Hosts the bridge inside the opencode server process and registers the browser_* tools.

02

Chrome extension

Connects to the bridge over WebSocket. Token-paired, chrome-extension:// origin auth, 20s ping.

03

CDP input in your tabs

The extension attaches chrome.debugger to a tab and dispatches input and navigation through the DevTools Protocol. It operates in your real profile, so it can act on pages you are signed in to.

what the installer does

What the installer does

A single shell script. Everything stays on the machine.

  • Clones or updates the canonical skills repo to ~/pear-ai-skills (idempotent on re-run).
  • Installs the skill into your assistant skill folders — opencode, codex, and claude.
  • Copies the opencode plugin (a single self-contained file) to ~/.config/opencode/plugins/.
  • Prints the two Chrome steps — load the unpacked extension, then run pair.
  • Nothing is transmitted off-host. Pairing is a token handshake over the loopback interface; the token travels in a URL fragment and is stored in a 0600 file.

enable it in chrome

Enable the extension

  1. Load the unpacked extension Open chrome://extensions, toggle Developer mode on, click Load unpacked, and select ~/pear-ai-skills/skills/chrome-bridge/bridge/extension.
  2. Pair Run node ~/pear-ai-skills/skills/chrome-bridge/bridge/bin/chrome-bridge.js pair. It finds the Chrome profile that has the extension and opens a self-pairing page there; the token is saved automatically. Then restart opencode so the plugin loads.

security notes

Security notes

  • Localhost only. The bridge binds 127.0.0.1:8823; it is not reachable from other hosts.
  • Token file. The pairing token lives in ~/.opencode-chrome-bridge/config.json with mode 0600. Any local process that can read that file can drive the browser.
  • Visible when driven. Chrome shows its “started debugging this browser” infobar on every tab the agent drives.
  • Permissions. The extension requests <all_urls> and debugger because it must be able to inject and act on any page. It has the same access to driven tabs that you do, including authenticated pages.
