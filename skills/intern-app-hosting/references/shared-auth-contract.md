# Shared Auth Contract

## Overview

All Pear intern apps share one Google OAuth client. The shared auth service at `auth.intern.pearcommerce.com` owns the Google callback. Hosted apps never register their own Google redirect URIs — they only need to trust the signed token returned by the shared service.

Never rotate or replace `GOOGLE_CLIENT_ID` or `GOOGLE_CLIENT_SECRET` while fixing a single app. Those credentials belong to `auth-intern` and changing them is a global auth change that can break every app using shared login. For app-specific auth failures, debug callback routing, cookies/state, hosted domain checks, and `AUTH_SHARED_SECRET` first. Only perform a Google OAuth client rotation when explicitly requested as a coordinated global auth operation.

---

## Stable Google Redirect URI

Only this URI is registered in Google Cloud:

```
https://auth.intern.pearcommerce.com/auth/google/callback
```

---

## Login Flow

### 1. App initiates login

The hosted app generates a `state` (CSRF token) and `nonce`, stores them temporarily (cookie or session), then redirects the user to:

```
GET https://auth.intern.pearcommerce.com/auth/google/start
```

Query parameters:

| Param | Description |
|-------|-------------|
| `return_to` | App's callback URL, e.g. `https://sample.intern.pearcommerce.com/auth/google/callback` |
| `state` | CSRF value generated by the app |
| `nonce` | One-time nonce generated by the app |
| `hosted_domain` | Allowed Google Workspace domain, e.g. `pearcommerce.com` |
| `app_name` | Label for this app, e.g. `sample` |

### 2. Shared auth service handles Google

The shared service:
1. Redirects to Google using the shared OAuth client
2. Receives the Google callback at the stable URI
3. Validates the Google identity
4. Enforces the requested `hosted_domain`
5. Creates a short-lived signed `session_token`
6. Redirects back to `return_to` with `state` and `session_token` as query params

### 3. App validates and creates local session

The hosted app:
1. Validates the returned `state` matches what it stored
2. Validates the `session_token` signature using `AUTH_SHARED_SECRET`
3. Validates the nonce and `hosted_domain` claims inside the token
4. Creates a local session (signed cookie for Workers, `express-session` for Lightsail)
5. Clears temporary auth state (state + nonce)
6. Redirects user to their intended destination

## Environment Variables

```bash
AUTH_BASE_URL=https://auth.intern.pearcommerce.com
AUTH_CALLBACK_URL=https://<app-hostname>/auth/google/callback
AUTH_SHARED_SECRET=<retrieve from Pear secrets store>
GOOGLE_HOSTED_DOMAIN=pearcommerce.com
```

Use the exact raw `SecretString` from AWS Secrets Manager secret `intern-app-hosting-auth-shared-secret` in `us-east-1` for `AUTH_SHARED_SECRET`. Do not parse the SecretString as JSON, select an inner field, trim quotes, or rotate the shared token secret while fixing a single app. If a callback reports `Bad shared auth token signature`, update only the affected app's Worker secret first.

For Lightsail/Node apps, also add:

```bash
SESSION_SECRET=<random strong secret>
```

## Session Implementation

**Cloudflare Workers:**
- Use a signed cookie for session state
- No server-side session store needed
- Validate the signed cookie on each request

**Lightsail / Node (Express):**
- Use `express-session` with `connect.sid`
- `SESSION_SECRET` signs the session cookie
- Session store can be in-memory for simple apps; use Redis or similar for production-grade persistence

---

## Security Notes

- The `session_token` from the shared auth service is short-lived — validate it promptly and don't store it long-term
- Always validate `state` before touching the token to prevent CSRF
- Always validate `hosted_domain` inside the token to prevent cross-app token reuse
- The hosted app's `/auth/google/callback` route is an app route, not the Google OAuth callback — it receives the redirect from the shared auth service, not from Google directly
